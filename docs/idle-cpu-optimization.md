# 后台空闲 CPU 与按需调度优化

本轮根据空闲集群调度器唤醒占比高的分析，保留复制/快照按需定时、发现持久化合并和周期追赶游标复用。数据帧发送锁合并经过独立测量后撤回。Raft 的 CommitTimeout、心跳与选举参数没有调整；生产部署由既有发布流程处理。

## 行为边界

### 复制批次

原 `publishLoop` 每 2ms 唤醒，即使没有复制批次。现在仅在存在待发桶时启动 timer，按最早一桶的 `firstQueuedAt + maxBatchDelay` 等待。后续事件不会延后已启动的 deadline，32 事件/64KiB 满批仍立即刷新。满批使所有桶清空时停表，关闭仍执行原 drain/flush 流程。取消后的传输 enqueue 沿用原上下文取消语义。

没有 timer 且通道已有积压时，先消费当前队列中至多一个满批的剩余事件；每条使用本来要读取的入队时间检查最早 deadline，到期即停止合并。这样连续满批可直接刷空，避免每 32 条先启表再取消，同时没有新增等待窗口。

这不是把间隔放慢：窗口仍是 2ms；原 ticker 相位可能让单条事件在第一次扫描时尚未满 2ms，再等一个 tick，新实现按该批次自身截止时间等待。操作系统调度、构建与网络发送仍可能产生额外延迟，不能承诺硬实时上限。

### 快照摘要与请求

原摘要循环每 25ms 扫描。现在由容量 1 的非阻塞通知唤醒，或者等待现有状态里的最近期限：

- 普通脏摘要遵守最近摘要活动后的 250ms 和最近排队后的 25ms 限制，immediate 只绕过 250ms。
- 请求单次响应超时仍为 30s，失败后的退避仍为 1/2/4/8/16/30s，超时先进入退避，再到期重发。
- 没有可执行工作时停表。pending pull 完成/取消、请求开始/失败/完成、会话激活/替换/关闭、合成 mesh session 创建，以及时钟门控恢复均通知重算；被时钟门控挡住的工作不空转轮询。
- 通知只提示重读真实状态，不清空扫描期间到达的通知。新增脏标记版本和 active-session 校验，防止旧摘要发送完成时清掉期间新增的修复通知或替换会话的工作。

只有循环自己操作 timer，通知不获取 Manager/session 锁；调度器在 Manager 锁内拷贝活跃 peer 信息，释放后再读取 session 状态。Snapshot 构建与网络发送均在锁外执行。生产者列表的 map 长度也移入原有锁内读取。

这轮没有增加 snapshot 请求总寿命，也没有给原本无期限的 pending pull 新增超时规则，避免把状态机修复混入 CPU 调度优化。

### 发现持久化

同轮广告仍逐项验证、实时更新内存拓扑与 generation，再按 URL 合并最终记录，一次事务写入。SQL 自身判断是否需要更新，不引入“尚未提交但认为已成功”的进程缓存：

- 新 URL、新状态、来源、错误、非空密钥或真实连接时间变化立即写入。
- 只有观测时间或 generation 变化时，距上次持久化观测满一分钟才写入；持久化 generation 仍只增不减。
- 空密钥、nil 连接时间不能擦除已有值；Manager 将同一连接毫秒时间稳定映射为 Logical=0，避免持久化时产生的 HLC logical 变化被误认为重新连接。
- 批量先全部验证，执行或提交失败整批回滚；内存拓扑继续工作，下一轮广告仍能重新尝试。来源实际交替变化仍立即写入，不能把多来源广告一律限成每分钟一次。

因此数据库里的 lastSeen/generation 允许短暂落后，实时发现与路由使用内存状态；监控不能把该持久化观测时间当作逐包实时心跳。

条件 SQL 初版在单条关键变化场景曾因重复 prepare 变慢。最终在 SQLite 后端复用既有固定语句集合；Pebble 后端也在 Bind/Close 生命周期维护一条 SQLite 元数据语句。两种后端都验证了单连接初始化、实际执行和关闭释放；未初始化的单条入口仍可回退到普通 SQL。

### 周期追赶与发送记账

周期 catchup 每轮用一次 `ListOriginCursors`，所有 peer 共享本轮快照；即时响应处理仍通过原入口读取最新游标。缺失 origin 从零开始，pending 去重、发送失败取消和逐 peer 继续处理保持原语义。快照查询失败时该轮不发起新 pull。

曾将成功数据帧的业务活跃时间、发送字节和失败计数合并到一次 runtime 锁内处理；微基准有小幅收益，但真实路径的尾延迟不理想，最终恢复原实现。签名、TLS 和质量统计语义没有调整。

## 测量方法

环境为 Linux amd64、Intel Core i5-12400，Go `go1.26.2`，`GOWORK=off`，`CGO_CFLAGS='-O2 -D_LARGEFILE64_SOURCE -D_GNU_SOURCE'`。

比较基线是工作树快照 `a512052`：底层 HEAD 为 `86f4b26`，并包含上一轮尚未提交的 SQL、编码等优化。本轮仅比较后台优化增量，避免将上一轮收益重复计入。

先分别构建相同工具链的测试二进制和服务端，再顺序测量；构建、功能测试、race 和性能采样不并发。基线用 overlay 加入同一份独立 benchmark。前后按 AB、BA 交替，每场景三至四轮，以中位数比较；不同 benchmark 的 CPU/wall 降幅不可相加。

- 发送记账微基准分别测单线程与 4 个执行者争用同一 runtime；丢弃连接、noop signer，不含真实网络/HMAC。另跑既有 direct/forwarded 路由基准。
- publish 稀疏基准逐条发布并等待会话队列确认，固定 1000 次，报告 p95/p99；满批基准每次 32 事件，包含实际发布循环和接收，不含网络、存储写入。
- 发现基准用 SQLite trigger 统计已提交 INSERT/UPDATE 行，并覆盖重复、关键字段变化和批量；计数查询在计时外。
- catchup 基准比较同一组已追平 peer/origin 的完整一轮，基线执行原逐 peer 路径，候选执行正式共享入口。
- 真实投递覆盖七节点 WebSocket transient 与三节点/1000 在线用户的持久化 direct 路径。
- 空闲集群为 5 节点 WebSocket 全连接，SQLite 数据在 SSD ext4，启用同一组 5 voter Raft，`GOMAXPROCS=2`/节点。各轮预热后采固定区间的 `/proc` user+system CPU ticks、各线程 voluntary/nonvoluntary 上下文切换及 I/O；所有节点需存活。该环境不含生产 TCP mTLS、跨境 RTT 或业务负载。

## 结果

### 空闲集群

最初完整候选（含随后撤回的发送锁合并）的三轮顺序为 A/B、B/A、A/B；每段预热 15 秒后采 60 秒，CPU tick 为 100Hz。全部阶段五个节点存活、Raft 存储存在，采样前观测到 40 个关联的已建立 socket 端点。

| 轮次 | 基线 CPU ticks | 优化 CPU ticks | CPU 变化 | 基线上下文切换 | 优化上下文切换 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 373 | 179 | -52.0% | 598262 | 151244 |
| 2 | 353 | 207 | -41.4% | 596203 | 154619 |
| 3 | 923 | 523 | -43.3% | 586395 | 165028 |
| 中位数 | 373 | 207 | **-44.5%** | 596203 | 154619 |

上下文切换中位数下降 **74.1%**。五节点合计 CPU 中位数为 3.73s → 2.07s/60s，约相当于 6.22% → 3.45% 单核；不是单节点占用，也不是生产环境承诺。各轮的配对 CPU 降幅在 41%～52% 之间。

第三轮两边 CPU 都明显升高。主机是共享开发环境，采样期间观察到其他项目的测试/数据库进程；保留所有原始样本，使用配对顺序和中位数，不把异常轮剔除。上下文切换仍接近前两轮。进程计数含用户态和系统态，不含编译时间。

`/proc/io/write_bytes` 中位数从 6430720 降至 2211840 字节（-65.6%）。这是整个服务进程的 I/O，不能全部归因于发现表；独立 trigger 基准另行确认发现行的实际写入。

撤回发送锁合并后，对最终只保留 1/3/4 的版本再次做 A/B、B/A 确认，每段预热 15 秒后采 30 秒：

| 轮次 | 基线 CPU ticks | 最终 CPU ticks | 基线上下文切换 | 最终上下文切换 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 165 | 78 | 299526 | 73124 |
| 2 | 175 | 82 | 298174 | 73901 |
| 中位数 | 170 | 80（-52.9%） | 298850 | 73512.5（-75.4%） |

最终五节点合计 CPU 为 1.70s → 0.80s/30s；文件系统写入量中位数为 3057664 → 1052672 字节（-65.6%）。这组是较短的最终确认，与前面的三轮 60 秒试验分别报告，不混合不同采样时长。两阶段都确认了大幅减少空闲唤醒和 CPU 的方向，不能据此保证生产环境有相同百分比。

### 局部路径

| 场景 | 基线 → 优化 | 变化/写入 |
| --- | ---: | --- |
| 稀疏 publish 平均延迟 | 2273.84 → 2136.59µs | -6.0% |
| 稀疏 publish p95 / p99 | 3200 / 3250 → 2186.5 / 2231µs | -31.7% / -31.4% |
| 满批 publish，每 op 32 事件 | 38.542 → 35.568µs | -7.7%，分配不变 |
| 单条重复发现记录 | 40.99 → 5.01µs | -87.8%，实际更新 1 → 0 行/op |
| 单条关键字段变化 | 41.69 → 22.28µs | -46.6%，两边都立即更新 1 行/op |
| 64 条重复发现记录 | 2627.99 → 278.99µs | -89.4%，实际更新 64 → 0 行/op |
| 64 条关键字段变化 | 2699.58 → 436.20µs | -83.8%，两边均更新 64 行/op |
| 完整广告处理，同轮 16 URL 各重复 4 次且改变来源 | 2759.59 → 201.90µs | -92.7%，实际更新 64 → 16 行/op |
| 一轮追赶，6 peer × 6 origin | 220.17 → 14.98µs | -93.2%，查询 36 → 1，分配 1146 → 96 次 |
| 一轮追赶，1 peer × 1 origin | 6.27 → 6.44µs | +2.7%，仅每轮一次，不主张该规模有收益 |

满批初版 timer 频繁启停曾慢约 3%，最终增加有限积压消费后，按前后各六轮、每轮固定 50000 个满批复测，得到上表结果。不能把这些局部降幅相加为全服务 CPU 降幅。

### 真实投递与数据帧锁合并

最终只保留 1/3/4 的版本另以前后各三轮确认吞吐：七节点 WebSocket transient 并发投递，256B / 4KiB 耗时中位数从 31.895 / 54.920µs 降至 29.411 / 52.774µs（-7.8% / -3.9%）。三节点、1000 在线用户、256B 持久化 direct 投递从 3.994 降至 3.397ms，p95 从 5.172 降至 4.362ms，p99 从 10.460 到 10.520ms（+0.6%，基本持平）。后者的进程 CPU（含相同夹具建立/清理）中位数为 2.646 → 2.630s，没有明显变化。

持久化复杂夹具有明显后台分配波动，优化版本 `B/op` 中位数高于基线、单轮基线也出现过大幅额外分配；不把此场景的分配数据当作稳定收益。纯 publish 基准的分配量则保持不变。

短七节点串行延迟基准的小包 p95/p99 曾升高，因此进一步做基线/完整候选/恢复旧发送锁三版本轮转，各六轮、每轮每种正文固定 20000 次逐条确认：

| 正文与指标 | 基线（µs） | 完整候选（µs） | 最终保留 1/3/4（µs） |
| --- | ---: | ---: | ---: |
| 256B 平均 | 150.922 | 156.838 | 137.230（-9.1%） |
| 256B p95 | 285.40 | 296.45 | 255.85（-10.4%） |
| 256B p99 | 520.05 | 628.65（+20.9%） | 452.55（-13.0%） |
| 4KiB 平均 | 250.542 | 245.549 | 230.386（-8.0%） |
| 4KiB p95 | 491.00 | 488.05 | 446.65（-9.0%） |
| 4KiB p99 | 955.20 | 1141.15（+19.5%） | 786.60（-17.7%） |

锁合并在独立微基准中改善约 2%～7%，仍不足以抵消这组真实路径的 p99 回退。因此最终 `internal/mesh/runtime.go` 恢复为基线，保留独立测试和 benchmark，便于以后尝试更有针对性的实现。局部锁操作次数减少不能直接推断整条链路的尾延迟。

以上为本机回环测试，没有测量生产饱和负载或跨境 TCP mTLS 的所有情况；没有观察到最终保留版本存在稳定的吞吐/尾延迟退化。

## 验证与复测

新增测试覆盖批次首次入队 deadline、稀疏消息无后续输入也刷新、关闭 drain、空闲/请求/退避期限、pull 完成和时钟恢复唤醒、旧发送与新 dirty/会话替换竞争，以及发现真实写入次数、一分钟边界、事务回滚、失败重试和重启恢复。发送记账验证普通/Owned 发送、失败/超时/取消、控制/测量分支、关闭及邻接删除。

最终保留版本的完整 `go test ./... -count=1 -timeout=5m`、cluster/store/mesh 全包 `-race -count=1 -timeout=3m` 和启动 smoke 均已通过。独立只读审查未发现新增的可确认语义或并发问题。
