# 持续差链路上的控制查询降级

健康 TCP mTLS 直连继续优先。运行时在既有路由规划器外，仅对**本地发起的 `TrafficControlQuery`** 增加测量判定；入站转发查询、共识、复制、快照、有序点对点流继续走原规划器。点对点流的连接固定和重选实现保持原有行为。

## 进入备用路径

同时满足以下条件时，将控制查询改为目标节点的健康直连备用连接：

1. 默认规划结果是目标节点的 TCP 直连；TCP 和备用连接均至少已有 8 个有效探测样本。
2. 备用连接已建立，近期没有发送失败、探测退化或长时间未回复的探测；`RTT EWMA + 2 × jitter EWMA + 既有故障惩罚` 不超过1000ms，为3秒会话查询预算保留余量。该值是保守估计，不是实际延迟分位数；备用有适度抖动但显著优于主链路时仍可使用。
3. 备用最后有效响应足够新鲜。新鲜度兼顾原有空闲备用探测间隔，最长不超过失联超时的一半（默认 15 秒）。
4. TCP 使用相同的 `RTT EWMA + 2 × jitter EWMA + 既有故障惩罚` 评分，同时达到备用的两倍，且至少高 100ms。
5. 上述质量差持续至少 10 秒，期间有至少 3 个新的 TCP 探测样本。单次 RTT 尖峰、重复查询或没有新样本的时间流逝不会触发切换。
6. 当前拓扑仍声明该备用传输出站启用，且对应到目标的已建立直连链路存在。规划和发送均从满足质量门槛的备用连接中选取最低评分者；发送前重新检查，规划后新增的零样本连接不能绕过门槛。普通及入站转发查询继续沿用原有连接选择。

仅考虑到同一目标的直接备用连接，不引入新的中转路径或跨传输桥接规则。多个备用传输按实际成本选取，成本相同时按传输枚举稳定排序。

## 恢复与失效

进入备用状态后，TCP 恢复到健康、评分不超过1000ms，并达到“最多高于备用 50ms”或“最多高于备用 25%”之一，持续至少 10 秒且有至少 3 个新 TCP 样本，才恢复默认 TCP 偏好。中间质量区间保持备用，避免在进入阈值附近反复切换。

备用失去健康条件会立即退出该降级状态。TCP 或备用连接断开、换为新的连接时清理旧状态，重新观察新连接；既有规划器继续处理断连和发送错误。状态按直接邻居保存，随相关连接退出清理。

使用已有探测与单调时钟，不新增定时器、网络探测、配置项或协议字段，也不主动建立新连接。这里的质量是应用层 RTT、抖动和发送故障成本；实现没有读取内核 TCP 重传率，因此不能承诺某一重传百分比必然触发切换。实际查询路由可通过原有路由查询/运维接口观察。

## 验证

`runtime_query_fallback_test.go` 验证持续样本要求、短时波动和中断重置、恢复迟滞、不健康/过期/未知备用拒选、拓扑与出站能力约束、其他流量及入站转发与原规划器一致、真实查询发送走备用、连接断开清理。既有 stream 路径固定、重选和路由策略测试也参与完整测试与 race 检查。

```sh
GOWORK=off go test -race ./internal/mesh ./internal/cluster -count=1
GOWORK=off go test ./internal/mesh -run ControlQueryFallback -v -count=1
```
