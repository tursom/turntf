# 稳定集群控制流量优化

## 拓扑公告

普通拓扑发布和收到公告后的转发按远端节点去重。同一邻居的 mTLS、WSS、双向连接共用一个发送任务，
每个来源仅保留最新的待发送公告，版本先比较运行时纪元，再比较生成号。
任务按控制链路的 RTT、抖动和故障成本选择一条连接；一次发送成功后结束，失败时尝试该邻居的其他连接。
单个慢邻居不会阻塞其他邻居或入站消息分发。

新连接仍直接补齐缓存拓扑，周期刷新仍保留；因此本改动不承诺整个集群每个版本只传输一次。
有序 stream 的路径固定与切换规则不变。

## 在线状态摘要

用户上下线仍在50ms窗口合并为增量。旧版、非直接邻居和能力未知的目标继续每500ms接收一个完整权威分片，
16个分片每8秒轮转一次。

直接邻居所有已建立连接的 NodeHello 均声明 `presence_digest_supported` 时，普通轮转改为每8秒发送一次节点内容摘要。
摘要是确定性排序后的在线用户、会话数量、传输提示和登录摘要的 SHA-256，包含来源节点及运行时纪元，
不包含各分片 generation。比较实际内容可以发现丢失早期增量、随后收到更高版本增量的情况。

摘要不匹配时，接收端发送修复请求，来源返回16个完整权威分片；新节点还每64秒保留一轮完整轮转修复。
摘要和请求不直接修改在线缓存，也不推进分片 generation。旧运行时纪元的控制消息会被忽略。
接收任务只排队，后台按目标及任务类型合并请求；完整修复每个目标最多一个发送任务，16个分片共用10秒预算，
拥塞邻居不会阻塞在线状态增量循环，失败后由下一次摘要重新校验。
定向修复不会清除其他邻居尚未收到的用户增量。

协议新增内容为可选 NodeHello 能力位、OnlinePresenceUpdate 控制模式和摘要字段。
旧节点不会收到新控制模式，滚动升级与回退继续使用原有完整分片。多跳能力未知时不推断支持。
这些字段只属于服务端集群协议，客户端 SDK API 无需调整。

## 在途会话查询

同一目标节点、同一运行时纪元、同一用户的并发查询共享一次实际网格请求，不缓存成功或错误结果。
各调用者的取消和截止时间互不影响；最后一个等待者离开时取消底层查询，并在返回前清理 pending request。
共享请求沿用3秒查询预算，由 Manager 的生命周期管理；停止服务时取消并等待任务退出。
查询结果为各调用者的独立切片，不改变权限判断和实时会话语义。

该改动减少拥塞时的重复控制请求，不承诺修复公网丢包、TCP重传或路由器问题。

## 空闲备用连接探测

主控制连接、正在承载业务的连接和不稳定连接保持原有探测频率。已有至少8次测量、没有发送失败且抖动受控的
空闲备用连接，将探测发送间隔增加至原周期的4倍，最多为失联超时的三分之一；默认由2秒变为8秒。
检查循环仍每2秒执行，主连接退化或备用连接出现业务活动后恢复原频率。

每次仍只允许一个在途探测，只接受匹配且通过时间校验的响应。
备用探测的截止时刻不晚于最近一次有效响应加原失联超时，因此不会因少发探测而额外延长原有失联判定上限。
已有 WebSocket 传输层心跳不变。

## 运维观察

`/ops/status` 的 `mesh.presence_sync` 提供按增量、完整分片、摘要和修复请求分类的本进程收发数量，
以及 OnlinePresenceUpdate protobuf 正文字节数，不包含转发、认证、TCP/TLS封装或重传。
邻接的 `probe_interval_ms` 表示最近一次实际探测采用的发送周期。

部署验证应同时检查消息收发、节点加入和退出、多跳与混合版本兼容、丢增量修复、并发取消及TCP半开连接回收。
线上对照需保留业务负载和重传统计；不能将不同负载窗口的接口差值直接归因于本次优化。
